# 2.0 Public API Diff

This document records the public API, crate and feature changes introduced by
the Phase 1 foundation work packages. Sections 1-4 describe **WP-1.1 —
Freeze/cut non-core features and dead code**; section 5 describes **WP-1.2 —
Normalized domain and client identity model**. It is the migration reference
for code that depended on the 1.9.x workspace; `docs/2.0-migration.md` will
link to it when the 2.0 migration guide lands.

The changes are source-breaking only for consumers of the internal workspace
crates. The `sito` binary's TOML schema, REST/API contracts and CLI are
unchanged except for the startup rejection described below.

## 1. RouterOS is now an optional crate

RouterOS DHCP lease synchronization (HTTP client, response parsing and the
background sync task) moved out of `sito-clients` into the new optional
`sito-routeros` crate. **The default `sito` build does not link it.**

| Before (1.9.5) | After (2.0) | Notes |
|---|---|---|
| `sito_clients::routeros::RouterOsConfig` | `sito_clients::RouterOsConfig` (unchanged path) | Plain serde data type only; no `reqwest`. |
| `sito_clients::RouterOsError` | `sito_routeros::RouterOsError` | Moved; adds `MissingTokenEnv` for a configured but unresolvable `token_env` (no basic-auth fallback). |
| `sito_clients::fetch_routeros_leases` | `sito_routeros::fetch_routeros_leases` | Moved. |
| `sito_clients::spawn_routeros_sync` | `sito_routeros::spawn_routeros_sync` | Moved. |
| `sito_clients::routeros::{RawRouterOsLease, ROUTEROS_REQUEST_TIMEOUT, build_routeros_client}` | `sito_routeros::{RawRouterOsLease, ROUTEROS_REQUEST_TIMEOUT, build_routeros_client}` | Moved. `RawRouterOsLease::into_lease` now takes `verified: bool`. |
| `sito_clients::RouterOsLease` | `sito_clients::RouterOsLease` (same path) | Registry matching stays in `sito-clients`; the struct gains `verified: bool`, true only for `https://` with certificate verification. Unverified leases are display-only and never identify clients. |
| `sito_clients` dependency `reqwest` | removed | The default build no longer links the RouterOS HTTP stack. |

### Build and feature changes

```toml
# crates/sito/Cargo.toml
[features]
routeros = ["dep:sito-routeros", "sito-api/routeros"]
```

| Crate | Feature | Effect |
|---|---|---|
| `sito` | `routeros` | Adds `dep:sito-routeros` and forwards `sito-api/routeros`. Not in `default`. |
| `sito-api` | `routeros` | Internal capability flag: configuration validation accepts an enabled `[integrations.mikrotik]`. It does not add a dependency. |

The optional crate honours the D15 security bar: environment proxies are
disabled (`.no_proxy()`), error bodies are capped at 4 KiB, a configured but
unresolvable `token_env` is an error rather than a basic-auth fallback, and a
lease is identity-capable (`verified = true`) only when **both** conditions
hold: the `url` uses `https://` and `allow_invalid_certs = false`. A plaintext
`http://` URL (even with `allow_invalid_certs = false`) and an insecure-TLS
client both produce `verified = false`; such leases are display-only and the
registry never grants a group/trusted/MAC identity from them. The sync task
logs an explicit warning for either case, and `enabled = true` with a scheme
other than `http://`/`https://` is rejected by config validation.

```bash
cargo build -p sito                       # default: no sito-routeros
cargo build -p sito --features routeros   # optional integration included
```

`cargo tree -p sito --locked` must not contain `sito-routeros`;
`cargo tree -p sito --features routeros --locked` must contain it. The
integration remains **experimental**.

The default binary still links `reqwest` for unrelated features (ACME
HTTP-01/TLS-ALPN and the self-updater); the RouterOS-specific proof is the
absence of the `sito-routeros` crate and the rejection of an enabled
`[integrations.mikrotik]`.

A build without the feature rejects `[integrations.mikrotik] enabled = true`
during startup, `check-config` and API writes with an error naming the
`routeros` feature. It is never silently ignored. A disabled section is still
accepted in every build.

## 3. Dependency graph changes

Removed unused direct dependencies:

| Crate | Removed dependency |
|---|---|
| `sito` | `serde` |
| `sito-core` | `arc-swap` |
| `sito-clients` | `reqwest` |
| `sito-rewrites` | `serde_json`, `thiserror` |
| `sito-ha` | `anyhow`, `rustls-pki-types` |
| `sito-upstream` | `thiserror` |
| `sito-test` | `blake3`, `webpki-roots` |

The workspace `tokio` dependency no longer enables `full`. Each crate now
requests only the features it uses (for example `sito-transport` requests
`macros`, `time`, `sync`, `net` and `io-util`), so `cargo build -p sito`
does not pull Tokio's process/signal/fs surface into crates that never need it.
`rust-version` is unchanged.

`sito-stats` keeps its `sito-core` dependency: the deprecated compatibility
wrapper `cleanup_retention` still reads `StatsConfig::default()`, so the
historical "unused dependency" lead did not hold.

## 4. Non-Unix fallbacks

`sito-transport` already refuses non-Unix targets with `compile_error!` in
`lib.rs`, `udp.rs` and `pktinfo.rs`. The unreachable `#[cfg(not(unix))]`
permission fallbacks in `acme.rs` and the redundant `#[cfg(unix)]` gates were
deleted; Unix-only code is now unconditional inside the crate. Windows remains
unsupported.

## 5. WP-1.2 — Normalized domain and client identity model

WP-1.2 introduces canonical domain/network primitives in `sito-core` and moves
client policy onto an explicit identity-with-provenance model. It addresses
P1-9, P2-31..P2-35, P2-97..P2-99 and the IDN gaps.

### 5.1 New `sito-core::domain` API

```rust
pub struct NormalizedDomain(/* lowercase ASCII/punycode */);

impl NormalizedDomain {
    pub fn parse(raw: &str) -> Result<Self, DomainError>;      // IDN + wildcard + root
    pub fn parse_ascii(raw: &str) -> Result<Self, DomainError>; // historical wire form
    pub fn parse_idna(raw: &str) -> Result<Self, DomainError>;  // wire form with IDN
    pub fn root() -> Self;
    pub fn as_str(&self) -> &str;
    pub fn is_root(&self) -> bool;
    pub fn has_wildcard_labels(&self) -> bool;
    pub fn matches_suffix(&self, suffix: &Self) -> bool;
    pub fn is_strict_subdomain_of(&self, suffix: &Self) -> bool;
    pub fn into_string(self) -> String;
}
```

`NormalizedDomain` implements `Display`, `FromStr`, `TryFrom<&str>`,
`TryFrom<String>`, `Serialize` and `Deserialize`. Deserialization normalizes
(therefore `"EXAMPLE.COM."` becomes `"example.com"`), and serialization always
emits the canonical form.

`parse` converts raw Unicode/IDN labels to punycode, lowercases ASCII, strips
one trailing dot, validates label (63-byte) and name (253-byte) limits, keeps
wildcard labels (`*`, `*.example.com`, `*.banner.*`), and represents the root
as `"."`. `parse_ascii` and `parse_idna` preserve the historical wire contract:
raw Unicode, wildcards and the root are rejected where they were rejected
before. `DomainError` mirrors the former `ProtoError` normalization variants.

`sito_proto::normalize_domain` and `normalize_domain_or_idna` now delegate to
these constructors and map `DomainError` back to `ProtoError`, so their public
signatures and error type are unchanged.

### 5.2 New `sito-core::net` API

```rust
pub struct IpNetwork { /* address + prefix */ }

impl IpNetwork {
    pub fn new(addr: IpAddr, prefix: u8) -> Result<Self, CidrError>;
    pub fn parse(value: &str) -> Result<Self, CidrError>;
    pub fn addr(&self) -> IpAddr;
    pub fn prefix(&self) -> u8;
    pub fn contains(&self, target: IpAddr) -> bool;
    pub fn network_address(&self) -> IpAddr;
}

pub fn ip_in_subnet(network: IpAddr, prefix: u8, target: IpAddr) -> bool;
```

`IpNetwork` implements `Display`, `FromStr` and `Hash`. `CidrError` rejects
missing/extra separators, unparsable addresses and prefixes larger than 32
(IPv4) or 128 (IPv6). Membership tests always mask host bits and never match
across address families.

### 5.3 New `sito-core::client` API and `ClientContext` migration

```rust
pub enum IdentitySource {
    Ip, Cidr, Mac, TlsSni, DohPath, Secret, RouterOs,
}

pub struct ClientIdentity {
    pub ip: IpAddr,
    pub source: IdentitySource,
    pub authenticated: bool,
    pub name: Option<String>,
    pub group: Option<String>,
    pub mac: Option<String>,
}

impl ClientIdentity {
    pub fn from_context(ctx: &ClientContext) -> Option<Self>;
    pub fn may_match_secret_rules(&self) -> bool;
    pub fn may_match_client_exception(&self) -> bool;
}
```

`IdentitySource::is_trusted` follows D10: `Ip`, `Cidr`, `Mac`, `Secret` and
verified `RouterOs` are identity-capable; `TlsSni` and `DohPath` are
display/statistics-only. The two `may_match_*` methods are true only when the
identity is both authenticated and from a trusted source. The serde name of
every variant matches `IdentitySource::as_str()` (including `routeros`).

`ClientIdentityRef<'a>` is the borrowed form used on hot paths; it exposes
`ip`, `source`, `authenticated`, `name: Option<&str>`, `group` and `mac`, plus
the same `may_match_*` methods. `ClientContext::identity_ref()` returns it
without cloning strings.

`ClientContext` gains:

| Field / method | Change | Notes |
|---|---|---|
| `identity_source: Option<IdentitySource>` | new, `#[serde(default, skip_serializing_if = "Option::is_none")]` | Older serialized contexts deserialize with `None`. |
| `identity_ref()` / `identity()` | new | Borrowed and owned policy identities. Legacy in-process contexts that only populated `client_name`/`group` are treated as an authenticated IP identity; registry-produced contexts always carry an explicit source. |
| `may_match_secret_rules()` / `may_match_client_exception()` | new | Convenience wrappers over `identity_ref()`. |
| `ClientContext::with_id` | behaviour | Records `IdentitySource::DohPath`, unauthenticated. |
| `ClientContext::with_sni` | behaviour | Records `IdentitySource::TlsSni`, unauthenticated. |
| `ClientContext::with_authenticated_id` | behaviour | Records `IdentitySource::Secret` in addition to `id_authenticated = true`. |

`ClientRegistry::resolve` now records the matching source: exact IP (`Ip`),
CIDR (`Cidr`), ARP MAC configured on an entry (`Mac`), verified RouterOS lease
(`RouterOs`), configured secret (`Secret`), and otherwise the untrusted
wire-claimed `TlsSni`/`DohPath` label. A trusted RouterOS lease hostname copied
into `client_name` keeps `RouterOs` provenance. An unverified RouterOS lease
still never grants identity (WP-1.1 rule preserved). This tree has no
`trust_arp` setting; a MAC is identity only when the operator lists it on a
client entry, which is the configured-MAC-identity case of D10.

### 5.4 Policy now uses identity, never `ctx.id`

| Crate | Change | Migration |
|---|---|---|
| `sito-filter` | `$client` name/group/MAC matching requires `ClientIdentity::may_match_client_exception()`. | Wire-claimed DoH path/SNI labels never satisfy `$client`; IP/CIDR matchers still use the query source address. |
| `sito-rewrites` | `exception_clients` matches only an authenticated identity's name/group/MAC, or an IP/CIDR. | A raw `ClientContext::id` (even a registry-authenticated secret) no longer satisfies an exception; match the resolved client name/group/MAC instead. |

The `ctx.id` audit found no remaining policy use. `sito-clients` still consumes
`ctx.id` during identification (it is the credential being matched) and
transport/stats/tests use it for display only.

### 5.5 Other source-breaking changes

| Crate | Item | Change | Migration |
|---|---|---|---|
| `sito-filter` | `parser::ClientMatcher::Cidr { ip, prefix }` | replaced with `Cidr(IpNetwork)` | Use `IpNetwork::parse`/`IpNetwork::new`. |
| `sito-filter` | `parser::cidr_matches` | removed | Use `sito_core::ip_in_subnet` or `IpNetwork::contains`. |
| `sito-filter` | `parser::RuleModifiers::denyallow` | `Option<Vec<String>>` → `Option<Vec<NormalizedDomain>>` | Compare with `as_str()`/`matches_domain_suffix`; values are canonical punycode. |
| `sito-filter` | list pattern parsing | raw Unicode (IDN) domains, whole-label wildcards and prefix patterns are now accepted and normalized to punycode instead of silently dropping or never matching the rule; exact keys reject wildcard labels | Existing ASCII lists are unchanged. |
| `sito-cache` | `DnsCache::invalidate_domain` | normalizes the requested name with IDNA before matching cache keys, so Unicode names evict punycode entries | Callers may keep passing `Name::to_string()`; no API change. |
| `sito-rewrites` | rewrite domain parsing | invalid entries are skipped with a warning instead of being compared in raw form | Fix the config entry; valid IDN/trailing-dot entries still normalize. |
